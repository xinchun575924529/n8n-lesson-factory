### 附赠：工厂环境级坑（写进 SOP 的那种）
- 新导入工作流 CLI execute 必坑：`executeWorkflowTrigger` 必须 `typeVersion=1` 且 `settings` 为空，否则玄学报 “No active execution found”。
- `executeCommand` 节点 CLI 环境不可识别 → Code + `child_process` 替代。
- `jsonBody` 忘记以 `=` 开头 → 模板引用明文发给 LLM，**断言全过的质量级 bug**（教训：断言要看内容质量，不只看契约结构）。
- httpRequest 节点过后上游 item 全丢 → `$('关键节点').item.json` 回捞（坑⑦真机版）。

## 2. 防御工事一：轮询 + 熔断（修坑②）

把"Wait 20s 一次"升级为循环：
```
Generate Video → [Loop] Wait 60s → 拉 record-info
   → { response?.resultUrls ? 放行下载
      : 已轮询 8 次(8min) ? 熔断→错误网
      : 回到 Wait }
```
- 判空写法：`v?.data?.response?.resultUrls?.[0] ?? null`，**先验存在再消费**。
- 熔断次数写进 CONFIG 行（第三讲的配置同表设计正好用上）。

## 3. 防御工事二：错误网三连（补全模板）

```
任何失败节点 → Error Trigger（或 onError 输出）→
  1) 台账该键置 STATUS=ERROR（状态机合法第三值）
  2) 群机器人/Slack 告警（节点名 + runId + 输入摘要）
  3) 回执用户兜底话术："这条视频生成失败了，创意已留存，可重发触发重试"
```
B 级查错实录：mock 断链会"顺流而下"污染到终点才暴露，定位靠逐节点翻 runData——**有错误网，断在第一现场；没错误网，断在用户嘴里**。

## 4. 防御工事三：契约钉死（修坑④⑦）

- **契约测试进 CI**：把 A 级 U2/U3 的断言（stringify 配对无引号注入）做成导入预检脚本，改模板前先跑。
- **节点加 ID 引用**：表达式用 `$('node-id-xxx')` 风格或统一常量节点，降低重命名杀伤力；团队约定"节点名即 API，改名要 code review"。
- **Caption 闸门**抄第四讲代码，双字段留痕。

## 5. 防御工事四：收图选档统一（修坑①）

第一讲的 `photos[photos.length-1]` 统一选档 Code 节点，一处定江山；两处索引从此不存在不一致。

## 坑点提示

- 修坑顺序：先修"高严重度 × 高频触发"（①②④），再修契约类（⑦），最后补体验类（③⑥）。
